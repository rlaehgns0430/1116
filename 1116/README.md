비교 횟수
  데이터 크기가 커질수록 세 알고리즘 모두 비교 횟수가 완만하게 늘어납니다. 병합 정렬은 나뉜 배열을 순서대로 비교하기만 해서 비교 횟수가 가장 적게 나왔고
  힙 정렬은 heapify 할 때마다 왼쪽·오른쪽 자식 노드를 다 확인해야 해서 비교 횟수가 가장 많았습니다.

실행 시간
  실제 돌아가는 속도는 퀵 정렬이 가장 빠르고 힙 정렬이 가장 느렸습니다. 퀵 정렬은 배열의 옆 칸을 차례대로 훑으면서 처리해 CPU 캐시 효율이 좋은 반
  힙 정렬은 인덱스 위치를 이리저리 건너뛰면서 값을 바꾸다 보니 시간이 더 오래 걸렸습니다.

메모리 사용량
  힙 정렬과 퀵 정렬은 원래 배열 안에서 자리만 바꾸는 방식이라 재귀 호출 스택 외에 추가 메모리를 거의 쓰지 않았습니다. 
  반면 병합 정렬은 정렬된 값을 임시로 담아둘 배열을 따로 만들어야 해서 데이터 크기에 비례해 메모리를 가장 많이 사용했습니다.

퀵 정렬 피벗 선택별 차이
  랜덤 데이터라 세 방식 모두 큰 차이는 없었지만, Median-of-Three가 양끝과 중간값 중 중앙값을 골라주다 보니 분할이 가장 고르게 되어 비교 횟수와 재귀 스택(메모리)을 제일 적게 썼습니다.
  Random 방식은 매번 난수를 뽑는 과정 때문에 실행 시간이 조금 더 걸렸습니다.

## 2. 시간·공간 복잡도 및 메모리 측정 기준

복잡도: 평균 시간 복잡도는 세 정렬 모두 $O(n \log n)$이고(퀵 정렬 최악은 $O(n^2)$), 추가 공간 복잡도는 힙·퀵 정렬이 $O(\log n)$, 병합 정렬이 $O(n)$입니다.
메모리 계산 방법: 원본 배열 크기는 빼고, 정렬 도중 새로 할당한 임시 배열 크기와 재귀 함수가 호출되면서 쌓이는 스택 프레임 크기를 누적해 가장 많이 썼을 때의 바이트(Byte) 수를 측정했습니다.
